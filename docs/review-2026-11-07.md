## Baseline observations

- Live inventory: 100 records, zero duplicate identity keys, no discovery warnings.
- Window construction: approximately 0.15 seconds; completed inventory and
  settling: approximately 0.96 seconds in this run. These are observations, not
  a cross-machine performance guarantee.
- The real live capture was inspected locally at `/tmp/deeppurge-audit-before.png`.
  It is not committed because it contains the user's installed-app inventory.
- Existing native targeting, argument arrays, per-operation locking, exact path
  previews, unchecked data cleanup, symlink boundaries and Trash-only behavior
  are preserved. No additional cleanup matches are inferred from display names.
- PackageKit performs ordinary removal, not Debian purge; dependency-changing
  transactions are refused. Flatpak data remains optional. Snap snapshots follow
  snapd's policy. Privileged authentication and host APT/Snap uninstall remain
  unverified integration paths, not observed defects.

## References checked

[Flatpak command reference](https://docs.flatpak.org/en/latest/flatpak-command-reference.html)
supports querying native inventory and targeting an installation/ref;
[desktop entry precedence](https://specifications.freedesktop.org/desktop-entry/latest-single/)
keeps launcher metadata separate from package identity.
[Gio Trash](https://docs.gtk.org/gio/method.File.trash.html) can fail where trash
is unsupported, so the application retains its no-permanent-delete fallback.
[GTK icon API](https://docs.gtk.org/gtk3/method.Image.set_from_gicon.html) was
reviewed without assuming it proves slow-filesystem behavior.

## Completed changes and verification

Version **0.2.1** completes the selected batch. Flatpak failures now block both
absence verification and the shared-data cleanup guard. Activity corruption is
isolated from inventory and operation results; unique temporary files, validation
before truncation and rejection of shared/FIFO state files protect state writes.
Lock contention is distinguished from backend I/O errors. Failed scans expose a
persistent notice and accurate partial counts; failed full refreshes retain prior
records with removal disabled until retry succeeds. Protected, unverified and
shortcut-only actions have visible captions. Activity failures and cancellations
use distinct visual tones. Cleanup wording explains shared namespaces and links.

The final test run is documented in [verification evidence](verification.md).
Live inventory remained at 100 unique records without source warnings. A real
Flatpak details view was prepared and cancelled; no host uninstall was started.
Updated live captures are under ignored `artifacts/local/`, including
`live-after-wide.png`, `live-after-narrow.png` and
`live-native-flatpak-details.png`. Public screenshots are clearly identified
layout fixtures, including the new incomplete-scan state.

The native Flatpak fixture test still installs/removes only an isolated app and
separately trashes its selected data. Real Trash moves use temporary AppImage and
shortcut fixtures. Host PackageKit is exercised by read-only simulation only.
Existing privileged-authentication and APT/Snap destructive-integration limits
remain explicit; mocked failures do not establish those capabilities as tested.

## Recommended next improvements

1. **Recommended:** a disposable VM suite for PolicyKit acceptance/cancellation,
   APT dependency/lock failures and snapd snapshot/removal behavior. These are the
   largest remaining verification gaps for an uninstaller.
2. Incremental inventory publication so a slow daemon cannot hold back records
   from fast sources; include generation/shutdown tests before introducing caching.
3. A relocatable installer that installs assets and replaces an older launcher
   safely. The current checkout launcher works, but moving it still needs editing.

The completed changes are committed on the existing `main` branch; Git history
identifies the review commit. No remote history is replaced or force-pushed.
